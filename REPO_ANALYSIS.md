# SmartChef — Full Repository Analysis

SmartChef is a sophisticated, self-hosted recipe management and meal planning application built with a modern TypeScript stack. It features a unique "Matrioska" recipe engine, LLM-powered recipe extraction, and a P2P synchronization system with CRDTs for offline-first capabilities.

---

## 🏗️ Project Structure

The project is organized into three main areas:

- **`/backend`**: Node.js + Express API handling business logic, database interactions, LLM integration, and sync coordination.
- **`/frontend`**: React + Vite single-page application (SPA) providing a rich, responsive user interface.
- **`/shared`**: TypeScript type definitions shared between both ends to ensure end-to-end type safety.
- **`/db`**: SQL migrations for PostgreSQL schema management.
- **`/docker`**: Containerization setup for easy deployment.

## 📊 Data Model (PostgreSQL)

The schema is designed for high relational integrity and features specialized tables for offline-first synchronization:

### Core Tables
- **`ingredients` & `ingredient_categories`**: Hierarchical ingredient management with support for subtypes and density-based unit conversions.
- **`units` & `unit_conversions`**: Robust unit system supporting weight, volume, and count with conversion factors.
- **`recipes`**: The heart of the system. Supports "Matrioska" nesting (recipes as ingredients).
- **`recipe_ingredients`**: Join table that can point to either an `ingredient_id` OR a `sub_recipe_id`.
- **`recipe_steps` & `recipe_tools`**: Detailed instruction and equipment tracking.

### Planning & Logistics
- **`menus` & `menu_items`**: Weekly scheduling with meal types (breakfast, lunch, etc.) and serving overrides.
- **`shopping_lists` & `shopping_list_items`**: Aggregated ingredient lists derived from menus, featuring `source_details` to track exactly which recipe required which ingredient.

### Sync & CRDTs
- **`crdt_operations`**: Append-only log of all changes for P2P synchronization.
- **`known_devices`**: Registry for local network discovery.
- **`entity_clocks`**: Vector clock snapshots for efficient conflict detection.

## ⚙️ Backend Services

### 1. Matrioska Engine (`matrioska.engine.ts`)
A recursive algorithm that "explodes" a recipe into its base ingredients.
- **Recursive Resolution:** If a recipe contains sub-recipes (e.g., "Lasagna" contains "Bolognese Sauce"), the engine drills down until all base ingredients are found.
- **Portion Scaling:** Automatically scales all quantities based on the requested number of servings.
- **Aggregation:** Combines duplicate ingredients across different sub-recipes into a single line item for the final list.

### 2. LLM Parser (`llm.parser.ts`)
Integrates with Ollama to provide "Smart Import" capabilities.
- **URL/Text Parsing:** Can fetch content from a URL or take raw text and extract a structured recipe JSON.
- **Structured Extraction:** Uses a strict system prompt to ensure the LLM returns consistent fields like `prepTimeMin`, `servings`, and a cleaned list of `ingredients`.
- **Confidence Scoring:** Includes a confidence metric to alert users if the extraction might need manual review.

### 3. Sync & CRDT Services
- **Vector Clock Management:** Tracks causal ordering of operations to resolve conflicts across multiple devices without a central authority.
- **mDNS/Discovery:** (Likely handled in `mdns.service.ts`) for finding other SmartChef instances on the local network.

## 🖥️ Frontend Architecture

The React application is built around a central layout (`AppLayout.tsx`) and uses React Query for efficient caching.

### Pages Description

1. **Gallery (`/`)**: 
   The main dashboard displaying a grid of recipes with filtering and search capabilities.

2. **Import Page (`/import`)**: 
   Allows users to paste a URL or recipe text. It communicates with the LLM Parser service to preview and save new recipes.

3. **Recipe Detail (`/recipes/:id`)**: 
   A high-fidelity view of a recipe. Features a dynamic "Portions" slider that triggers the Matrioska Engine to recalculate ingredients in real-time.

4. **Menu Planner (`/menu`)**: 
   A calendar-based interface where users can drag and drop recipes into a weekly schedule.

5. **Shopping List (`/shopping`)**: 
   Generates an aggregated list of ingredients needed for the planned menu. Includes "source details" so users can see which recipes contributed to each item.

6. **Sync Panel (`/sync`)**: 
   Displays connectivity status with other devices, last sync times, and allows manual triggering of synchronization.

7. **Conflict Resolver (`/conflicts`)**: 
   A specialized UI for resolving "Sync Conflicts" when CRDTs cannot automatically determine the winner (e.g., two people edited the same recipe step simultaneously while offline).
